# sentinelsre/wrong-inventory-endpoint

An autonomous-SRE evaluation task. A live 3-service demo platform
(checkout → inventory → order-worker) is provisioned in the sandbox with a
configuration fault baked in at image build: `checkout-service`'s runtime
config `inventory_url` points at a dead endpoint (`127.0.0.1:8099`), so every
synthetic checkout transaction fails with HTTP 503.

The agent must diagnose the outage through the `sre-ops` CLI surface only,
apply the smallest safe remediation (config patch + reload), and verify
recovery. Hidden ground truth lives under `runtime/.verifier/`.

## Layout

- `environment/Dockerfile` — platform image; bakes the fault at build time
- `environment/payload/` — generated by `scripts/prepare_harbor_task.py`
  (copies of `demo_platform/`, `configs/`, `knowledge/` from repo root)
- `tests/test.sh` + `tests/verify.py` — outcome verifier →
  `/logs/verifier/reward.json` (config_fixed / service_healthy /
  synthetic_passed / policy_clean / aggregate reward)
- `solution/solve.sh` — oracle remediation via `sre-ops` only

## Regenerating the payload

```bash
uv run python scripts/prepare_harbor_task.py
```

## Running

```bash
uv run harbor run -c harbor/job.yaml --env-file .env
```
